What it is

This is a real-time simulation of a Solari split-flap departure board, like the old ones at Grand Central and Penn Station. It runs in a browser with WebGL through three.js. Everything it needs is in the folder, so it never loads anything from the internet.

Run it: double-click CT40.A9.Solari.html, then click once anywhere. Browsers keep sound muted until you click; a note at the top says so.

Why there's an embedded copy

Chrome and Firefox block fetch() of neighbouring files when a page is opened as file://. The page therefore does this:

  1. It tries the real JSON and WAV files first; this works when served.
  2. If the browser blocks that, it uses embedded.js and says so in the control bar.
  3. The Load JSON… button picks edited JSON files and works from file:// too. It tells fields from schedule by their content: columns+drums means fields, events means schedule.

Behaviour and design decisions

  • Board state at clock time T is every event with t <= T, applied in order. Reset, looping and loading all recompute the state from scratch, so the state is deterministic.
  • Drums only advance forward: changing A to E flips through B, C and D, then stops on E, like a real drum. A change such as E to A wraps around the whole drum. The alnum drum order is space A–Z 0–9 . - & / '. Characters that aren't on a drum show as blanks. Text is shown uppercase (board.uppercase).
  • Flap timing: flapMs is 110 per flap. A1 feedback asked for slower transitions than A1's, and 110 ms is my own choice; A1 and A2's actual values weren't available. The leaf falls with a gravity ease (s^1.6). Each cell starts after a random stagger of 0–140 ms (flapStaggerMs) so the board ripples.
  • Rendering: a single InstancedMesh draws everything in one draw call, with 3 instances per cell: the upper half, the lower half and the falling leaf. The leaf's front shows the old glyph's top half; its back shows the new glyph's bottom half. Every face comes from one canvas glyph atlas (Helvetica Neue / Helvetica / Arial bold), and wide letters are condensed. The gray split line is painted across the middle of every flap face. The colon is a printed plate with no line. The column labels are HTML and have no line.
  • Master clock: a flap clock at top centre showing h:mm:ss AM, drawn larger (clock.scale 1.45). Since A9 it clacks by default (clock.sound: true); the C key toggles it.
  • Columns, left to right: TRAIN (40) · STATUS (10) · FROM (12) · TO (12) · TIME (HH:MM AM) · GATE (3, right-aligned). The order follows the user's example line (description, status, destination, time), with FROM added. To reorder, rearrange columns in the fields JSON.
  • Status words: ON TIME, DELAYED, BOARDING, ALL ABOARD, DEPARTED, ARRIVING, ARRIVED, CANCELLED.
  • Fun early changes: at +4 s the North Carolina Special becomes DELAYED 10:01 AM (Raleigh), matching the user's example. Also: +9 s gate change, +14 s delay, +20 s gate change, +27 s cancellation, +30 s ARRIVING, +35 s delay. After that, trains depart or arrive and the rows ripple up, and new trains appear at the bottom.
  • Schedule: starts 9:58:00 AM and ends 10:28:00 AM, then loops back to the start.
  • Controls:
  • ▶ Forward (runs the clock), ■ Stop, ⟲ Reset (jumps to the start time and keeps the current run/stop state).
  • Speed −/+ in small steps from 0.1× to 60×, plus a 1× button. It starts at 1× (real time) and running.
  • Sound ON/OFF (on by default) and a volume slider (defaults to 100% since A6).
  • Size −/+: scales the clock and flaps only (the headings are fixed), 20–100%, default 70% since A8, remembered per version.
  • Keys: Space = run/stop, R = reset, +/− = speed, 1 = real time, M = mute, C = clock clack on/off, [ ] = board size.
  • Clock driving: the clock advances with requestAnimationFrame using performance.now() deltas multiplied by the speed. That fixes the A3 bug where Forward didn't advance the clock; this build was verified: stopped Δ = 0, 2 s at 1× ≈ 1.9 s, 2 s at 2× ≈ 3.9 s.
  • Sound:
  • Each flap landing plays a slice of one.wav (sound.slice = 0–0.11 s, the first, sharp metal strike). The second strike at about 0.13 s is skipped; set slice to [0, 0.274] to hear the whole sample.
  • Pitch jitter is ±8%, and the sound is panned left/right by the cell's position.
  • At most 5 voices start per frame (maxVoicesPerFrame), with gain scaled by √n. Everything goes through a compressor, so a whole-board change roars instead of clipping.

Version history (from the user's feedback)

  • A1: close, but the letter transitions were too fast. Wanted some fields to change after a few seconds "just for fun".
  • A2: "very wonderful". Asked for sound on by default, a harsher "metal clack" (the user once used a metal stapler sample), speed adjustment in small increments, and a volume control.
  • A3: broken. Forward didn't advance time, the sound was like hollow wood, and the default speed should be 1×.
  • A4: no feedback recorded.
  • A5: uses the user's own one.wav for the clack, fixes the Forward/clock problem, starts at 1×, has sound on by default with a volume slider and fine speed steps, adds separate FROM and TO fields, and runs as pure HTML/JS. The A1–A4 files weren't available in this chat, so A5 was rebuilt from the feedback above.
  • The user mentioned a reference picture ("what I would like it to look like"), but it didn't arrive in the A5/A6 chat. If it's available next time, match the layout to it.
  • A6: the user said A5 was too big on screen and there was no way to shrink it, and that the audio could be louder by default.
  • Size: added −/+ buttons (and the [ ] keys) in 5% steps from 20% to 100% of the window. The default is 70% (board.size in the fields JSON), and the browser remembers the choice. The board always scales to the window, so browser zoom (Ctrl −) alone didn't help, since zooming just refits the board.
  • Volume: the slider now defaults to 100% (it was 70%), and the browser remembers the setting. The sound chain is now voices → volume → compressor → make-up gain (sound.loudness, 2.5) → limiter (−3 dB) → speakers. Measured offline, a single clack is about 13 dB louder in RMS than in A5, and a 40-cell roar about 7 dB louder, with the limiter preventing clipping.
  • A7: the user said "the legend at top is fine, but everything from the time down is too big".
  • Two scales now: the title and column headings keep their A6 size (board.labelSize 0.7 of the window fit). The master clock and flap rows use their own size, board.size, which now defaults to 0.5 (it was 0.7).
  • Size −/+ and [ ] change only the clock and flaps. The headings stay fixed and their positions follow the columns.
  • Remembered settings are now stored per version (CT40.A9.Solari.size, .vol), so an old saved size can't override the new default.
  • A8: the user's A7 screenshot showed the real cause of "too big". High-DPI bug: the user's Windows display is scaled (≈150%). The canvas was sized with renderer.setSize(W, H, false), which never set its CSS size, so it displayed at its buffer size, i.e. devicePixelRatio (1.5) times too large and pushed down and right. The HTML labels were correct, so the flaps didn't line up with them.
  • Fix: setSize(W, H, true), the canvas CSS is now width:100vw; height:100vh, and the pixel ratio is re-read on resize. Verified at 1.25×, 1.5× and 2×: the canvas matches the window, and the TRAIN label and the first flap line up to 0.01 px. The A7 build was run at 1.5× as a control and reproduced the bug (a 1999 px canvas in a 1333 px window).
  • Default size is back to 0.7, the same as the headings, because A5–A7 sizes were all inflated by this bug. The headings still don't change with Size (labelSize 0.7).
  • Control bar: it can grow to two lines and the board layout measures its real height. The status note is shorter, so the bar fits on one line at 1333 px.
  • Testing lesson: always test with device_scale_factor 1.5 as well as 1, since the user's machine is high-DPI.
  • A9 (this build): the user said A8 "works great", but there was no clack when the clock's seconds flip. That was by design (clock.sound: false). It is now on by default (clock.sound: true).
  • C toggles the clock clack live and shows a brief on-screen note.
  • Verified with an instrumented test at a moment with no board events: exactly one clack per second, extra clacks when the tens digit rolls over, and none after pressing C.
